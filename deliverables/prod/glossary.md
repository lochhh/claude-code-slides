# Glossary

[← Back to index](index.md)

Key terms used across the Claude Code master guide.

| Term | Definition |
|------|------------|
| <a id="acceptedits-mode">**acceptEdits mode**</a> | A Claude Code permission mode (cycle with Shift+Tab) in which all file edits are automatically accepted without per-change prompts, enabling hands-off execution after a plan has been reviewed. |
| <a id="anchoring-bias">**Anchoring bias**</a> | The cognitive tendency of Claude to over-weight the first piece of information it receives; in debugging, supplying a suspected cause in the prompt makes Claude anchor on it even when the real cause is elsewhere. |
| <a id="arguments">**$ARGUMENTS**</a> | A placeholder token in custom slash command files that is replaced at invocation time with whatever text the user types after the command name, enabling parameterised reuse of a command. |
| <a id="at-file-reference">**@file reference**</a> | A syntax (`@path/to/file`) used in Claude Code prompts to insert the contents of a specific file into context, scoping attention without copy-pasting. |
| <a id="ccusage">**ccusage**</a> | A third-party CLI tool that reports Claude API token spend at per-session, per-day, and per-month granularity, including a live billing-window view; more detailed than the built-in `/cost` command. |
| <a id="claude-code-subagent-model">**CLAUDE_CODE_SUBAGENT_MODEL**</a> | An environment variable that sets the model used by spawned subagents, allowing the orchestrator to run on a powerful model while subagents run on a cheaper one. |
| <a id="claudemd">**CLAUDE.md**</a> | A Markdown file placed at the project root (or any directory level) that Claude reads at the start of every session to load project-specific conventions, prohibitions, and context. |
| <a id="compact">**/compact**</a> | A Claude Code slash command that compresses the current conversation transcript into a condensed summary, reducing token count while attempting to preserve key context. |
| <a id="constraint-based-prompting">**Constraint-based prompting**</a> | A prompting technique that imposes explicit scope limits (line count, allowed libraries, prohibited abstractions) upfront to prevent Claude from over-engineering or drifting outside the intended solution space. |
| <a id="context-compaction">**Context compaction**</a> | The process by which Claude summarises and compresses accumulated conversation history to free up space within the context window, either manually via `/compact` or automatically when the limit is near. |
| <a id="context-essentials">**context-essentials.md**</a> | A short supplementary file (typically 10–50 lines) imported into CLAUDE.md via `@` syntax that holds the most critical rules so they survive context compaction and are re-read at every session start. |
| <a id="context-fork">**Context fork**</a> | A skill or command configuration (`context: fork`) that runs the prompt in an isolated subagent context so that research or analysis tasks do not pollute the main conversation history. |
| <a id="context-rot">**Context rot**</a> | The gradual degradation of Claude's output quality as a session grows long and the conversation history fills with redundant tool results, intermediate reasoning, and superseded decisions. |
| <a id="context-utilization">**Context utilization**</a> | The percentage of the context window currently occupied by the conversation, visible via `/statusline`; proactive compaction is recommended at around 60% to prevent quality degradation. |
| <a id="context-window">**Context window**</a> | The maximum amount of text (measured in tokens) that Claude can hold in active memory at one time; once full, older content is either dropped or compacted. |
| <a id="context7">**Context7**</a> | An MCP server that fetches up-to-date library documentation (React, FastAPI, Next.js, etc.) at query time, replacing Claude's potentially outdated training-data knowledge of third-party APIs. |
| <a id="exit-code-2">**Exit code 2**</a> | The specific process exit code a hook script must return to unconditionally block the tool call that triggered the hook; exit code 1 only produces a warning and allows execution to continue. |
| <a id="extended-thinking">**Extended thinking**</a> | A Claude capability that allocates additional token budget for internal reasoning before producing an answer; it is the largest single cost lever and is controlled by the `MAX_THINKING_TOKENS` environment variable. |
| <a id="file-ownership">**File ownership**</a> | An explicit mapping (documented in CLAUDE.md or a task plan) that assigns each agent or worktree to a mutually exclusive set of directories, preventing merge conflicts in parallel development workflows. |
| <a id="git-worktree">**Git worktree**</a> | A Git feature that lets you check out multiple branches of the same repository into separate directories simultaneously, enabling independent Claude Code sessions to work on different features without interfering with each other's working trees. |
| <a id="gotchas-section">**Gotchas section**</a> | A CLAUDE.md section (often titled "Known footguns") that documents recurring project-specific mistakes and failure modes so Claude does not repeat them across sessions. |
| <a id="hooks">**Hooks**</a> | Deterministic shell scripts configured in Claude Code's settings that run automatically at defined lifecycle events (before/after tool calls, at session start, after each response) to enforce policies, format code, or inject context without LLM involvement. |
| <a id="irreplaceable-information">**Irreplaceable information**</a> | Context items—such as architectural decisions, discovered constraints, or agreed trade-offs—that cannot be regenerated by re-running a tool or re-reading a file, and so must be explicitly preserved during compaction. |
| <a id="jq">**jq**</a> | A command-line JSON processor used inside hook scripts to parse the structured JSON payload that Claude Code passes to hooks via stdin, allowing conditional logic based on tool name, file path, or command content. |
| <a id="keybindings-json">**keybindings.json**</a> | Claude Code's keyboard shortcut configuration file, which allows rebinding built-in actions such as `acceptAll`, `rejectAll`, and `openNewConversation` to custom key combinations. |
| <a id="layered-claudemd">**Layered CLAUDE.md**</a> | A pattern in which a root-level CLAUDE.md contains shared project-wide rules and each sub-package or service directory has its own CLAUDE.md with more specific rules; Claude loads the most locally scoped file. |
| <a id="lazy-loading">**Lazy loading**</a> | An MCP server option (`"lazy": true` in `.mcp.json`) that defers server startup until the first tool call targeting that server, reducing session initialisation time. |
| <a id="loop">/loop</a> | A Claude Code slash command that schedules a prompt to repeat on a fixed interval (e.g., every 5 minutes) for the duration of the session, useful for monitoring dev server logs or running periodic test checks. |
| <a id="max-thinking-tokens">**MAX_THINKING_TOKENS**</a> | An environment variable that caps the token budget allocated to extended thinking per request; setting it to a fixed value (e.g., 10000) prevents runaway costs on tasks that do not require deep reasoning. |
| <a id="mcp">**MCP (Model Context Protocol)**</a> | An open standard protocol that allows Claude Code to connect to external tool servers—databases, APIs, browsers, documentation fetchers—so Claude can query them natively during a session. |
| <a id="mcp-json">.mcp.json</a> | The configuration file (at project root or user home) that defines which MCP servers to load, their startup commands, environment variable bindings, and optional flags such as `lazy`. |
| <a id="memory">**Memory**</a> | The practice of writing durable notes to external files or a database during a session so that important findings survive a `/clear` or session restart, complementing compaction and clearing strategies. |
| <a id="orchestrator">**Orchestrator**</a> | The primary Claude Code session responsible for decomposing a task into subtasks, spawning subagents to execute them, and synthesising their results; runs on the most capable model in a multi-agent setup. |
| <a id="permissiondecision">**permissionDecision**</a> | A structured JSON key returned from a PreToolUse hook that instructs Claude Code whether to allow or deny the pending tool call programmatically, eliminating interactive permission dialogs for known-safe commands. |
| <a id="phase-based-sessions">**Phase-based sessions**</a> | A workflow discipline that divides long projects into discrete phases (e.g., architecture → implementation → testing) and starts a fresh Claude Code session at each phase boundary, passing only a phase summary forward instead of the full history. |
| <a id="plan-mode">**Plan mode**</a> | A Claude Code permission mode (reached by pressing Shift+Tab twice from default) in which Claude researches and proposes a plan without making any file changes, allowing review before execution begins. |
| <a id="port-offset">**Port offset**</a> | A convention for assigning distinct local port ranges to each parallel git worktree (e.g., main on 3000, feature/auth on 3010) to prevent dev servers from colliding when running simultaneously. |
| <a id="posttooluse">**PostToolUse**</a> | A hook event type that fires after a tool call completes successfully, used to trigger side effects such as running tests, formatting files, or logging activity without blocking the original operation. |
| <a id="pretooluse">**PreToolUse**</a> | A hook event type that fires before a tool call executes, giving the hook script the opportunity to inspect the pending action and either allow it, warn, or block it entirely via exit code 2. |
| <a id="project-level-mcp">**Project-level MCP**</a> | An MCP server configuration scoped to a specific repository by committing `.mcp.json` at the project root, so all team members automatically get the same servers when they open the project. |
| <a id="prompt-caching">**Prompt caching**</a> | An Anthropic API feature that caches repeated large context blocks (such as CLAUDE.md or architecture docs) between requests, reducing token costs by approximately 90% for the cached portion after the first use. |
| <a id="prompt-type-hook">**Prompt-type hook**</a> | A hook configuration (`"type": "prompt"`) that injects a text string directly into Claude's context rather than simply running a shell command, enabling programmatic context augmentation at lifecycle events. |
| <a id="reactive-updating">**Reactive updating**</a> | The practice of editing CLAUDE.md immediately whenever Claude repeats a project-specific mistake, so that each error permanently improves future session quality rather than recurring. |
| <a id="rewind">/rewind</a> | A Claude Code command that reverts the conversation to a previous checkpoint, discarding subsequent erroneous reasoning and allowing the user to re-prompt from a clean state. |
| <a id="sequential-thinking-mcp">**Sequential Thinking MCP**</a> | An MCP server that instructs Claude to break down complex problems into explicit sequential reasoning steps before generating code, reducing incorrect implementations on multi-step tasks. |
| <a id="sessionstart-hook">**SessionStart hook**</a> | A hook event type that fires once when a Claude Code session is initialised, used to inject environment context such as recent git commits, current branch, or project status into the session automatically. |
| <a id="shift-tab-permission-cycling">**Shift+Tab permission cycling**</a> | A keyboard shortcut in Claude Code that cycles the active permission mode in the sequence `default → acceptEdits → plan`, allowing rapid mode switching without typing mode names. |
| <a id="simplify">/simplify</a> | A Claude Code slash command that reviews recently generated code for unnecessary abstraction, redundant indirection, and over-engineering, and suggests a leaner implementation. |
| <a id="skill">**Skill**</a> | A Markdown file in the `.claude/skills/` directory that defines a recurring workflow with optional YAML frontmatter; unlike one-off slash commands, skills can be configured for auto-invocation based on pattern detection. |
| <a id="slash-command">**Slash command**</a> | A user-invocable shortcut in Claude Code prefixed with `/`; custom commands are created as Markdown files in `.claude/commands/` and can accept dynamic input via the `$ARGUMENTS` placeholder. |
| <a id="stop-hook">**Stop hook**</a> | A hook event type that fires after Claude produces each response, allowing the hook script to inspect the output, inject additional context, or block completion (with the `stop_hook_active` guard to prevent infinite loops). |
| <a id="stop-hook-active">**stop_hook_active**</a> | A boolean field in the JSON payload passed to a Stop hook indicating that the hook itself triggered the current stop event; hooks must check this field and exit early to avoid recursive infinite loops. |
| <a id="structured-exploration-prompt">**Structured exploration prompt**</a> | A prompt template that directs Claude to explore an unfamiliar codebase in a defined sequence (purpose → architecture → key files → gotchas) before attempting any changes, preventing wasted searches. |
| <a id="subagent">**Subagent**</a> | A Claude Code session spawned by an orchestrator to execute a scoped subtask in isolation; subagents have their own context window and can run in parallel with other subagents working on non-overlapping work. |
| <a id="user-level-mcp">**User-level MCP**</a> | An MCP server configuration stored in the user's home directory settings and available across all projects on the machine, used for personal tools such as calendar, notes, or individual API access. |
| <a id="userpromptsubmit-hook">**UserPromptSubmit hook**</a> | A hook event type that fires each time the user submits a prompt, enabling pre-processing such as injecting standard context, enforcing prompt templates, or logging input before Claude sees it. |
| <a id="yaml-frontmatter">**YAML frontmatter**</a> | A block of YAML metadata at the top of a slash command or skill file (delimited by `---`) that declares properties such as `allowed-tools`, `description`, and `context`, restricting and documenting the command's behaviour. |
